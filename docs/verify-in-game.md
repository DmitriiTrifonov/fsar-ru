# Проверка перевода в игре: алгоритм по шагам

Все команды из корня проекта. Python только `tools/venv/bin/python -I`. Ром собирается и окно melonDS перезапускается ТОЛЬКО по команде пользователя.

## 0. Что сломает проверку (прочитать один раз)
- **Раскладка рома.** Сейвстейты хранят таблицу файлов того рома, на котором сняты. Если у любого файла сдвинулось начало, состояние виснет на чёрном экране. `build_rom.py` сам дополняет нулями файлы, ставшие меньше, до размеров из `build/layout.json` (создаётся `scripts/layout_lock.py --make <ром, на котором сняты состояния>`) и печатает WARNING, если файл вырос. После сборки сравнить FAT (смещения начал в `header[0x48]`) с прошлым ромом; допустимо отличие только концов. Выросшую страницу сжать `lz10.compress_opt` (см. `SLOT` в `scripts/gfx_lost.py`).
- **Кнопки драйвера.** `keys <hex>` = маска НАЖАТЫХ кнопок, `keys 0` отпускает всё. `keys 0xFFF` зажимает все 12. Пользоваться `scripts/tas.py` / `emu_press`.
- **Касания.** После `emu_open` первое касание проходит всегда; в одной сессии после нескольких `load_state` и зажатых кнопок касания могут не доходить. Надёжнее новый процесс на каждую страницу (так сделано в `scripts/guide_shoot_all.py` и `scripts/tas.py`).
- **Окно пользователя.** Не закрывать и не перезапускать без команды («запусти эмуль», «рестартуй»). Скриншот окна только по «скрин»: `ID=$(tools/melon_window_id | head -1 | awk '{print $1}'); screencapture -x -o -l "$ID" dumps/shots/<имя>.png`.

## 1. Сборка нового рома (по команде пользователя)
1. Номер сборки N+1: `python3 -I scripts/build_rom.py --out=build/fsar-gfxN+1.nds` (старый ром, на котором открыто окно, не трогать).
2. Если нет `build/layout.json`: `tools/venv/bin/python -I scripts/layout_lock.py --make build/<ром с состояниями>.nds`.
3. Сравнить FAT нового и предыдущего ромов (смещения начал равны), размер файла рома тот же.
4. Скопировать состояния: `for i in 1 2 3 4 5 6 7 8; do cp build/fsar-gfxN.ml$i build/fsar-gfxN+1.ml$i; done` (опорные из `states/`: `katharine-first-connect.ml1`, `hotel-start.ml2`, `guide-grid.ml3`).
5. Закоммитить правки (`git add -A; git commit`), ром и состояния в git не входят.
6. По команде пользователя: `pkill -9 -f "MacOS/melonDS"; open -n -a /Applications/melonDS.app --args "$PWD/build/fsar-gfxN+1.nds"`.

## 2. Диалоги глав (основная проверка текста)
Нужно сохранение с пройденной игрой: `build/full/<ром>.sav` (чужой `fsar-eu-100pct.sav`, не в git; ром скопировать рядом как `build/full/<ром>.nds` не нужно, путь к ромy обычный, `--sav` отдельно).
1. Чекпоинты стартов заказов (один раз на ром): `for n in $(seq 0 18); do tools/venv/bin/python -I scripts/tas.py build/<ром>.nds macros/to_request.txt --sav build/full/<ром>.sav --save-dir dumps/emu/req --set N=$n; done; cp dumps/emu/req/cp_request_*.ml1 states/requests/`.
2. Прогнать реплики: `tools/venv/bin/python -I scripts/tas.py build/<ром>.nds macros/walk_request.txt --set N=<заказ> --save-dir dumps/emu/walk` (60 нажатий A, кадр после каждой; число и паузу менять в макросе `walk r$N 60 90`).
3. Контактные листы только из окна реплики: `tools/venv/bin/python -I scripts/walk_sheets.py dumps/emu/walk r<N>` (4×15 реплик на лист, `--full` — целые кадры верхнего экрана). Открыть листы `Read`-ом.
4. Что искать: текст за красной рамкой окна, 4-я строка, налезание на портрет, английские остатки, неверный говорящий, пропавшие реплики. Сверять со строками таблицы `text/ru.csv` (по ID сцены).
5. Правка текста: `scripts/set_ru.py`/`tr_bulk.py` → `insert.py` → пересборка → повторить шаги выше (старые чекпоинты остаются годными, пока раскладка рома та же; сцену со старым текстом сейвстейт показывает старый текст, поэтому для проверки правки текста чекпоинт брать ДО загрузки сцены, т.е. пересоздавать заново `to_request.txt`).
6. **Полный проход катсцен без ручного счёта:** `tas.py <ром> macros/auto_request.txt --set N=<заказ> MAX=400 --save-dir dumps/emu/auto` жмёт A, пока экран не перестанет меняться, сохраняет только кадры с окном реплики (`a<N>_kkk.png`) и на остановке пишет `a<N>_stall.ml1`. ~15 с на заказ. Затем `scripts/check_walk.py dumps/emu/auto a0 a1 ...` ищет по пикселям 4-ю строку, текст у края экрана и ниже окна (на gfx16 замечаний нет; правее всего чернила x=244). Результат: R-00 24 реплики, R-03 24, R-15 173 (вся катсцена), остальные 10–31, дальше свободная ходьба по отелю.
7. **Дальше остановки** сюжет идёт ходьбой (D-pad двигает Мондо) и событиями на карте. Случайный блуждатель (`roam`, `macros/roam.txt`) не помог: упирается в запертую дверь и повторяет одну реплику. Рабочий путь: пользователь доходит до нужного места в GUI, сохраняет слот, файл `.mlN` копируется и проигрывается `macros/auto_state.txt --set CP=<файл> NAME=<имя>`; для частых мест добавить `press`/`touch` в макрос.
8. Ограничение: макрос жмёт только A, поэтому свободные участки (ходьба, допросы, выбор ответов, Катарина) он не пройдёт; для них делать чекпоинты руками в GUI или добавлять команды `press`/`touch` в макрос.

## 3. Картинки: Guide
1. Сейвстейт сетки страниц: `states/guide-grid.ml3` (копия слота 3 на ром, снят на экране сетки Гида).
2. Все страницы разом: `tools/venv/bin/python -I scripts/guide_shoot_all.py build/<ром>.nds states/guide-grid.ml3 <страницы...>` → `dumps/emu/guide/rNN.png` (нижние экраны, прокрутка касанием стрелки ▼ (235,137), 3 колонки). Страниц 2, 19 в сетке нет, 49 не переведена.
3. Перед тем смотреть страницу офлайн: `gfx_render_all.py` пересобирает все режимы (blocks/lines/frames); `gfx_render.py` на странице режима lines/frames затирает результат, не запускать отдельно.
4. Результаты фиксировать в `docs/guide-review.md` (статус каждой страницы).

## 4. Картинки: LostList (карточки)
1. Опорное состояние: слот 5 «перед столом» в комнате Мондо (`build/<ром>.ml5`, до открытия карточки; файл карточки подгружается из рома при открытии).
2. Нужный номер карточки: `python3 scripts/make_list_state.py <ром-без-.nds> 6:3 7:4 8:6` кладёт копию слота 5 с номером (слово по адресу ARM9 `0x02078638`) в слоты 6–8 (r03, r04, r06; r00 = номер 0, номера 12 и 13 нет).
3. Пользователь загружает слот, открывает карточку (подойти к столу, A, далее по сцене; карточка в «ЗАМЕТКИ/НАХОДКИ»), пишет «скрин»; снимок окна — по команде из п. 0.
4. Фон-шапка карточки: `scripts/stage4_lostbg.py` (`lostBG_u`); страницы: `scripts/gfx_lost.py lostSTR_rNN` (TSV `text/gfx/LostList/*.tsv`; `--skel` ПЕРЕЗАПИСЫВАЕТ TSV — не запускать без нужды).

## 5. Спрайты и интерфейс
Спрайты подменяются в состояниях `scripts/patch_state_gfx.py` (для `.pobj` работает, для длинных лент `.pbg` нет). Меню Катарины: слот 1 `states/katharine-first-connect.ml1`; PUSH («ЖМИ») — ввод кода, касание в цифровую панель.

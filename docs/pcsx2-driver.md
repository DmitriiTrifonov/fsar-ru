# Управление PCSX2 из скриптов и MCP (2026-11-09)

Зачем: проверять PS2-русификатор в игре без ручного прохождения (снимки реплик, дампы памяти, загрузка состояний). Аналог `fsar-emu` для DS.

## Состав
| Файл | Что |
|---|---|
| `scripts/pcsx2_ctl.py` | библиотека и CLI: запуск, PINE, ввод, снимки, выгрузка состояния |
| `scripts/pcsx2_mcp.py` | MCP-сервер `fsar-pcsx2` (в `.mcp.json`), оборачивает функции выше |
| `tools/pcsx2-ctl/pcsx2key.swift` | помощник macOS: события клавиш (CGEvent на pid), поиск окна; собирается `swiftc -O pcsx2key.swift -o pcsx2key` (бинарник не в git) |
| `build/pcsx2-profile/` | изолированный профиль PCSX2 (создаётся сам, не в git) |

## Как устроено
1. **Изолированный профиль.** PCSX2 запускается с `-datapath build/pcsx2-profile` (данные кладёт в подпапку `PCSX2/`). Ini собирается из ini пользователя (`make_profile`): включён PINE на слоте 28012, BIOS берётся по абсолютному пути из `~/Library/Application Support/PCSX2/bios`, ввод только с клавиатуры (SDL и мышь выключены, чтобы физический геймпад не мешал), хоткеи убраны, кроме F8 (снимок). Настройки и окно пользователя не трогаются, у обычного PCSX2 слот PINE 28011, не пересекаемся.
2. **PINE** (встроенный сокет PCSX2, `$TMPDIR/pcsx2.sock.28012`): пакет = `u32 длина` (вместе с этим полем) + команды; ответ = `u32 длина`, байт результата (0 ок, 0xFF ошибка), данные. Используем: чтение `Read8/Read64` (пачками до 40 тыс. команд за пакет, около 1 МБ/с), запись `Write8`, `SaveState/LoadState` по слоту, `Title`, `Status` (0 идёт, 1 пауза, 2 нет игры). Слать по одному пакету за раз: параллельные запросы могут повесить PCSX2.
3. **Ввод.** Кнопки PS2 привязаны к клавишам, которые Qt узнаёт по коду независимо от раскладки: Cross=F13, Circle=F14, Triangle=F15, Square=F16, Start=F17, Select=F18, Up=Home, Down=End, Left=PageUp, Right=PageDown, L1=F19, R1=F20, L2=Delete, R2=Insert. Буквы не годятся: при русской раскладке они не распознаются. Нажатия шлёт `pcsx2key` (`CGEventPostToPid`), терминалу нужно разрешение «Универсальный доступ».
4. **Фокус.** Игра получает кнопки, только если окно PCSX2 активно, поэтому `press` перед нажатием выводит его на передний план (osascript, System Events). Хоткеи (F8, пробел) работают и без фокуса.
5. **Снимки.** `screencapture` у терминала прав не имеет, поэтому снимок = хоткей F8 самого PCSX2. PNG (1704×1278) пишется медленно, драйвер ждёт конец файла (чанк IEND) и копирует его. Один снимок занимает 3–8 с.
6. **Выгрузка памяти.** `dump`: `SaveState` в слот → архив `.p2s` (zip) → `7zz x` достаёт `eeMemory.bin` (32 МБ, EE RAM) и `GS.bin` (видеопамять) в `dumps/pcsx2/<имя>/`. Остальное (поиск байтов, диффы) делается скриптами по файлам.

## Команды CLI
```
python3 -I scripts/pcsx2_ctl.py open <iso> [состояние.p2s]   # запуск, ждёт ответа PINE (до 60 с)
python3 -I scripts/pcsx2_ctl.py press <кнопки> [hold_ms] [wait_ms]   # CROSS, CIRCLE, START, UP… через +
python3 -I scripts/pcsx2_ctl.py shot <png>
python3 -I scripts/pcsx2_ctl.py read <hex-адрес> <байт>
python3 -I scripts/pcsx2_ctl.py dump <папка> [слот]
python3 -I scripts/pcsx2_ctl.py status | save <слот> | load <слот> | quit
```
MCP-инструменты: `pcsx2_open`, `pcsx2_press`, `pcsx2_screenshot`, `pcsx2_read_mem`, `pcsx2_find`, `pcsx2_dump_state`, `pcsx2_load_state`, `pcsx2_status`, `pcsx2_quit` (подхватываются после перезапуска Claude Code).

## Правила и грабли
- Состояния пользователя (`~/Library/Application Support/PCSX2/sstates/*.p2s`) открывать через `open <iso> <состояние>`; сами файлы не менять. Состояние хранит уже загруженную сцену, поэтому правки диалога видны только в новой игре или после перезагрузки сцены.
- Сохранение пользователя копируется в `build/pcsx2-profile/PCSX2/memcards/Mcd001.ps2` (копия; резерв `build/pcsx2-profile/saved/`). Своей карты нет: без неё игра идёт как новая, с ней на старте экран «Hello!! MEMORY CARD» (нужен Cross).
- Управление в игре: подтверждение в меню — Circle, отмена — Cross, Start пропускает заставки и демо. Главное меню: Play Start / Request / Movie / Option (текст английский).
- Ввод не доходит, если активно другое окно или идёт чужая раскладка (F-клавиши раскладке не подвластны).
- Закрывать только свой экземпляр (`quit` по pid из `build/pcsx2-profile/pcsx2.pid`).
- Не перезапускать PCSX2 пользователя и не править его ini.

## Чем проверялось
Запуск английского и русифицированного образов, чтение EE RAM (пролог, `YOSHI.BIN` в памяти), загрузка состояния с панелью Катарины, снимки, нажатия до главного меню и подтверждение пункта Circle'ом.

## Прогулка по диалогу
`tools/venv/bin/python -I scripts/pcsx2_walk.py <префикс> <N> [кнопка] [пауза_мс]` — N раз нажать (по умолчанию CIRCLE) и снять кадр в `dumps/pcsx2/walk/`; `--sheet <префикс>` собирает контактный лист. Путь до главы: Play Start → (Request) → список R-00… (по 4 на странице, NEXT листает) → Down нужное число раз → Circle. Проверено 2026-11-09: R-01 запускается, русская реплика «Доброе утро, мистер Мондо.» отображается в окне диалога. Снимок занимает 3–8 с, поэтому полный прогон всех 6615 реплик не делаем, а берём выборку по главам.

## Навигация по меню (черновик, 2026-11-09)
`scripts/pcsx2_nav.py request` пытается дойти до списка заказов по снимкам (`classify` по цветовым пробам). Не работает надёжно: на главном меню (ключи, Play Start / Request / Movie / Option) классификатор отвечает «list», а подсвеченный пункт на снимке не виден (выделение — бледный градиент полосы, мигает). Запомненный курсор (пункт остаётся с прошлого визита) делает слепые «Down + Circle» ненадёжными: так открывались Option и Movie. Что дальше: определять выделенную полосу по яркости (у выбранной градиент белеет, как «Save/Load» в Option), либо заранее сохранить состояние прямо на списке R-00… и грузить его (`load <слот>`).
